# Documentation for fetcher.py
## IMPORTANT
1. Please make sure you have a valid Steam API key before running fetcher.py.
2. Please make sure you have enough storage space to store the jsons that fetcher.py will download (for this project, upwards of a GB or more)
3. Please keep in mind that you may need to run fetcher.py multiple times depending on the size of the group you're querying for two reasons: Steam API has per-diem API call limits, and also in order to avoid being rate-limited I set a delay of 1 second between API calls. It took me over 8 hours to make all the calls for this project.
4. Please ensure that you rename steam_ids.txt and gamesCache to steam_ids_inUse.txt and gamesCacheInUse respectively after you've run fetcher.py. This is to make sure you don't accidentally overwrite previous data on future runs.
5. The program assumes that you've followed the above steps, as well as that the Steam group is valid. The program was not built to handle instances where this is not the case.

## Functionality
How to interface with fetcher.py:
1. Fetch Steam IDs from a given Steam group as XML files, extract the IDs, and save them to a file named steam_ids.txt. You will be prompted to enter the name of the Steam group you wish to grab the IDs from - this is CASE SENSITIVE.
2. Fetch game libraries and related information (see: README_data.md) for each Steam ID in steam_ids.txt using repeated calls to the Steam API. Each user's data is saved in a separate json file named [steamid].json in a folder named gamesCache. You MUST have a steam_ids.txt file in the same directory as fetcher.py that is populated with at least one Steam ID for this functionality to behave as intended.

# Documentation for steamfetch.py
## IMPORTANT
1. Make sure you've run fetcher.py at least once in order to create a gamesCache folder.
2. Please rename the gamesCache folder generated by fetcher.py to "gamesCacheInUse" (this is done so that accidental runs of fetcher.py do not overwrite the existing data in our active gamesCache folder).

## Functionality
How to interface with steamfetch.py:
1. When you run steamfetch.py, the program will either load an existing graph from a file called steam_graph.gpickle. If this file does not exist, it will build the graph from the data in the gamesCacheInUse folder. Building the graph may take several minutes. If a new graph is built, it will prompt you to either save the graph, or skip saving the graph. Remember that saving the graph may take sveral minutes, and may take up a large amount of storage space. It is not recommended to save the graph if you only plan on running the program once.
2. After the graph is either loaded or constructed, you will be presented with a set of five options:
    1. Search for game by keyword. This will prompt the user to enter a keyword, and then will return a list of games and game IDs whose titles contain that keyword. It is recommended to use this first if the user does not have a game ID in mind for the rest of the options.
    2. Get game recommendation(s). The user will be prompted to enter a game ID, as well as a number of recommendations to receive. The program will then print a list of recommended games, in descending order of recommendation strength, based on the strength of the connections between the entered game and that game's neighbors in the graph. This printed list will be in the format of [Name], [gameID], [RecommendationStrength]. It will be of the specified length. Both inputs must be integers.
    3. Find the shortest path between two games. The user will be prompted to enter two game IDs. The program will then print the shortest path between the two games using a BFS algorithm. The printed path will be in the form of [gameID], [Name] for each game on the path. It will also print the length of the path (the number of edges). Inputs must be ints.
    4. Find the most central games. The program will ask the user for a number to limit results by, then calculate centrality for each of the games in the graph with a simple formula (number of neighbors / total nodes - 1). It will print the most central games in descending order of centrality value. The format will be [gameID], [Name], [CentralityValue]. It will display only the number of results entered by the user. Input needs to be an int.
    5. Exit the program.
3. The program will prompt the user to see if they would like to do another task after each task is completed, until they decide to exit.

# Network Structure
The graph is a weighted networkx graph.

Each node is a game represented by its appid, or game ID.

Each edge is a connection between two games that are shared in the library of at least one user. Connection strength, or edge weight, is determined by a weighted formula that takes the log of the minimum playtime between the two games for each user that owns both games, then sums this value for all users that own both games. This is to give edge weights that take into account both player counts and playtime, exclude games that are not played, and also to try and minimize the effect of games that users play a very large amount.
